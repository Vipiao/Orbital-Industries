## Decisions (Markus, 2026-10-13)

1. **CPU/GPU placement agreement is deferred.** The first iteration generates on the GPU and
   does not try to match a CPU twin. The design must leave room for it: a patch can be filled
   from caller-supplied records instead of generated, which is how exact collision arrives
   later.
2. **Everything is in the body's frame, and the SSBO index is passed in**, so the surface, the
   water and the scattered objects cite one transform and move together.
3. **Shadows follow the CDLOD caster-tier scheme**: sorted so a near cascade draws only near
   patches and each further cascade draws more.
4. **Objects end at a range limit** (superseded below: hard cutoff for now, fade later).
   Matching the terrain colour to the forest beyond it is Markus's to do later.
5. **The per-object record may be shrunk** from the recipe's 48 bytes, where that is safe.

## Decisions (Markus, 2026-10-13, second round)

- Name is `ScatterHandler`, in `src/graphics/scatter/`; vocabulary patch / candidate / item / kind.
- Markus's main goal right now is understanding the code: small, pedagogical sub-steps, no
  temporary code to review (a step need not compile into anything visible).
- Comments in plain, direct English, not the terse style of the existing engine comments;
  no step names (E1, E4...) in code.
- Keep it simple, no bloat. Details are added iteratively, by Markus's request.
- Range limit: hard cutoff at the kind's maximum distance for now. Fading comes later.
- Impostors are treated as just another LOD mesh, so the pipeline is uniform; the vertex
  shader detects a camera-facing LOD and turns it.
- Test assets: generate a tree mesh once, at several LODs, and save it in `media/`.
- Budget: keep it cheap; Markus measures on the RTX 4070 machine himself.

## Decisions (Markus, 2026-10-21)

- GPU generation comes before culling and drawing; CPU agreement waits for G4.
- `addPatch` loses its `items` parameter; G4 brings the records path back.
